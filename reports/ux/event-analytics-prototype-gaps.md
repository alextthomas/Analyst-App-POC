# Event Analytics: UX prototype gap analysis (Phase 3)

Inputs: `docs/ux/event-analytics.md` (revision 2, draft, not approved) and `prototypes/event-analytics/src/**` (commit c749551).
Method: the original list of builder guesses was not saved, so it was re-derived by reading the spec and every prototype screen side by side. Neither the spec nor the prototype was changed.
Build check: `npm run build` in `prototypes/event-analytics` (`tsc --noEmit && vite build`) passed: 41 modules transformed, built in 591 ms. The build wrote `dist/` (ignored by the prototype .gitignore).

Type: (a) spec silent or incomplete, the prototype had to choose; (b) spec contradicts itself; (c) spec describes something the prototype could not represent as written.
All "Suggested resolution" entries are suggestions for the Product Owner / UX Lead only. Line numbers refer to `prototypes/event-analytics/src/`.

## Prototype defects (spec is clear, the prototype deviates)

- D-1 S-4 state "Permission-denied (unauthenticated)" should go to S-1 (S-4 state table); the prototype shows S-18 for any `permission-denied` state (App.tsx:102-103, 235; dash.tsx:22-25).
- D-2 S-1 requires the first field to receive focus and VM-1 text linked to the field through `aria-describedby`; the shared `Page` heading steals focus after `autoFocus`, and VM-1 is shown only in the summary (ui.tsx:19-22; auth.tsx:49-51, 102-106).
- D-3 S-2 requires "exactly 6 digits"; the code input allows 8 characters (auth.tsx:180; accepted and rejected only on submit).
- D-4 S-19 "Success (user)" text is exactly "Password set. Sign in."; the prototype appends " Other sessions of the account end." and omits the same behaviour for admins (auth.tsx:503); AC-16.8 describes behaviour, not copy.
- D-5 The 13-month check uses `setUTCMonth(+13)`, which overflows for month-end starts (for example 31 Jan) and gives a wrong limit (dash.tsx:161-163).
- D-6 C-6 says controls that depend on loading data are disabled; Gate removes content instead (ui.tsx:96-98).
- D-7 S-9 select-all is checked whenever the selection equals the list, and replayed events stay in the list regardless of outcome (admin1:709, 623-627); the replay outcomes are alternated by index, not driven by data (admin1:625).
- D-8 The idle warning and polling intervals are fixed demo values (idle warning only on demand, export polling 3 s instead of 10 s); noted in the prototype hints and acceptable for a throwaway (App.tsx:160; admin2:109).
