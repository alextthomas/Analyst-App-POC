- C-5 Passwords, TOTP codes, credential secrets and one-time links never appear in any screen after their single display (AC-16.3, AC-17.1, AC-16.2).
- C-6 Generic states used in every screen table:
  - Loading: a visible and announced busy indicator in place of the content; controls that depend on the data are disabled. On a write screen this applies to the table and to the form together: the form controls are disabled while either is loading (G-18).
  - Generic error (server or network failure): "Something went wrong. Your change was not saved. Try again. If the problem continues, contact a platform admin." (read-only screens: "Something went wrong. The data could not be loaded. Try again.") with a Retry action. No stack trace, no identifiers.   - Idle warning (UX-D-6): 2 minutes before the 30-minute idle timeout (AC-8.2) a dialog states "Your session will end in 2 minutes because of inactivity." with the action "Stay signed in". Choosing it keeps the session. It is announced to assistive technology when it opens and focus moves to the action. When a step-up, confirmation or one-time secret dialog is already open, the warning shows over it, and the open dialog and its input stay (UX-D-42). While a one-time secret or link is on display the warning adds: "A secret or link on display is lost if the session ends." (draft copy).
  - Session ended (idle 30 minutes, AC-8.2, or account disabled, AC-16.2): on every screen the user is taken to S-1, which shows the banner "Your session has ended. Sign in again." (C-6 as written; the per-screen "Session ended" rows in the screen tables mean this redirect and define no in-place variant) (G-6). Unsaved form input is not preserved (UX-D-6); this applies to session end only, while a live session keeps input across step-up (UX-D-8). A one-time secret or link on display when the session ends is lost and cannot be re-shown (C-5, UX-D-13). Signing out by choice also goes to S-1, with an empty form and without the banner, because the banner is for idle or disabled-account endings only.

## 3. Journeys (one per UI-facing story)

### J-5 (US-5): View the overview of an application

- Entry: S-4 after sign-in, selecting an entitled application.
- Steps: 1. Select application. 2. S-5 loads with the application selected in step 1 (a selection always wins); the other defaults are the last 7 days, meaning the 7 complete UTC days ending yesterday (today is not selectable; UX-D-32), and all event types (UX-D-7). The default application, the first alphabetically by application name (the tenant id, S-4), applies only when S-5 is opened with no application selected, for example by direct entry (UX-D-7 "defaults on first open"; G-2). 3. Total events, unique users, events-over-time and top 10 event types appear. 4. Suppressed cells show the suppressed marker and a statement that displayed cells may sum to less than the total.
- Exit: user changes filters (J-6), picks another application, or signs out.
- Error branches: no events in range, empty state (AC-5.3); query failure, generic error with Retry; range shorter than one whole UTC day, not selectable (AC-5.6; the date control is a native date picker with ISO format YYYY-MM-DD, whole days only, UX-D-33); session ended, S-1; application not entitled, S-18 (J-7).

### J-6 (US-6): Filter and compare

- Entry: S-5.
- Steps: 1. Choose application, start date, end date, event type. 2. Apply. 3. All figures reflect exactly the filter; active filters are listed and each can be cleared, plus "Clear all". Clearing a filter that always has a value (application, start, end) resets it to the UX-D-7 defaults; "Clear all" returns all filters to the defaults; start and end form one "date range" chip (UX-D-36). 4. Turn on "Compare with previous period" (the same length immediately before the range, UX-D-9); the toggle acts at once, without Apply (UX-D-37). 5. Both periods and percentage change are shown.
- Exit: filters cleared or user leaves.
- Error branches: end before start, or range longer than 396 days (the same limit as retention, UX-D-34; the PRD states 13 months, PI-24), validation message, query not run (AC-6.2); a start and end on the same day is valid (VM-7 refuses only an end before the start); a previous period that begins before the data retention horizon shows "n/a" for the comparison (UX-D-35); percent change from a zero previous value shows "n/a" (UX-D-9); a suppressed compared cell shows "—" with an explanatory tooltip (UX-D-10); query failure, generic error.

### J-7 (US-7): See only entitled applications

- Entry: S-4 or a direct URL or API call for another tenant.
- Steps: 1. S-4 lists only entitled applications. 2. Selecting one opens S-5.
- Exit: S-5, or S-4 empty state.
- Error branches: user entitled to none, empty application list (AC-7.2); request for tenant B by a user entitled to A only, S-18 (the same "not found" page, UX-D-29) and no tenant B data (AC-7.1); entitlement revoked mid-session, next query shows S-18 (effect within 60 s, AC-9.2).

### J-8 (US-8): Sign in, MFA, step-up, lockout

- Entry: any dashboard or admin URL without a session.
- Steps (user): 1. Redirect to S-1 (AC-8.1). 2. Enter username and password. 3. S-4 with entitled applications only and no admin function (AC-8.2).
- Steps (admin): 1. S-1 password. 2. S-2 TOTP code. 3. Ingestion health (S-8), with side navigation to the other admin screens (UX-D-2). 4. On a REQ-27 action with last authentication older than 5 minutes, S-3 opens; on success the action continues with its input kept, on failure it stays blocked (AC-8.5, UX-D-8).
- Exit: signed in; or locked out; or signed out; session ends after 30 minutes idle, with a warning 2 minutes before and a "Stay signed in" action (AC-8.2, UX-D-6).
- Error branches: wrong password, generic failure; 5 consecutive failures in 15 minutes, account refused for 15 minutes then allowed automatically (AC-8.3), and the screen shows the same generic sign-in failure without revealing the lock or the remaining time (UX-D-4); wrong TOTP counts together with password failures (AC-8.6); reused TOTP code rejected (AC-8.7); source throttle and global throttle refusal: pending design (AC-8.8, CR-036, UX-Q-5 deferred to Phase 4); correct password with no valid TOTP, no admin access (AC-8.4); failed step-up attempts: pending design (CR-029, UX-Q-3 deferred to Phase 4); unlock by another admin after step-up (S-15).

### J-9 (US-9): Manage tenants and entitlements

- Entry: admin side navigation, Tenants (S-6) or Entitlements (S-7).
- Steps (tenant): 1. New tenant. 2. Enter unique id, department owner, privacy-notice URL. 3. Save. 4. Tenant appears in list with the privacy-notice URL (AC-9.5).
- Steps (entitlement): 1. Choose user and tenant. 2. Grant (step-up) or revoke (confirmation, C-7). 3. Save. 4. Message states it takes effect for new queries within 60 seconds.
- Exit: list updated.
- Error branches: duplicate or missing field, field-level messages and nothing changes (AC-9.4); step-up fails, action not performed; user role opens an admin screen, S-18 and an audit entry (AC-9.3).

### J-10 (US-10): Monitor health and handle dead letters

- Entry: Ingestion health (S-8, the admin landing), then Dead-letter events (S-9).
- Steps: 1. S-8 shows throughput, lag, dead-letter count and refused-publish count per tenant, auto-refreshed every 30 seconds with a pause control (UX-D-19). 2. Open a tenant's dead letters in S-9. 3. Select an event, step-up, view masked payload. 4. Optionally reveal one masked value (one at a time, UX-D-52) with a reason of 10 to 500 characters and step-up (reason first, then step-up, UX-D-43); it is visible for 60 seconds and can be re-hidden (UX-D-21). 5. Replay, or discard (confirmation, C-7), selected events.
- Exit: list updated; actions audited.
- Error branches: unparseable body, never displayed and cannot be revealed (AC-10.6; such an event can be selected for Discard, and Replay is not offered for it, UX-D-51); replay of an event that still fails validation or is already stored (AC-10.2, AC-15.6); health data unavailable, error state, an unavailable tenant shows "unknown"; step-up fails; reason missing or out of length on reveal.

### J-11 (US-11): Run access and erasure for a subject

- Entry: Data-subject requests (S-10).
- Steps (access): 1. Enter verification reference (free text, up to 100 characters). 2. Enter 1 to 20 (tenant, user id) pairs and tick, per pair, that the reference covers that tenant (UX-D-24). 3. Step-up. 4. Run access. 5. Status while generating (within 15 minutes): queued, generating, ready or failed, updated every 10 seconds (UX-D-22). 6. Download JSON; expires and is deleted after 7 days.
- Steps (erasure): as above, run erasure: step-up, then the C-7 confirmation (UX-D-44), then execution. Outcome per store is shown; note on unparseable dead letters (AC-11.7).
- Exit: result shown; audit entry written.
- Error branches: pair whose tenant is not covered by the verification reference, refused with message and listed (AC-11.1, UX-D-24; the per-pair checkbox is the only control in the UI, and VM-22 stays as the text of a server refusal, UX-D-45; if every pair is refused nothing runs, the refused pairs are listed and VM-58 is shown; what the server checks the reference against: RO-2); no data held, "no data is held" (AC-11.4); one store fails, per-store outcome shown and the failed stores can be re-run for erasure (UX-D-23); status, download and expiry are reached from a per-tenant request list showing only masked reference, time (UTC), status and, for an access request, the export expiry; it holds no user id, no pseudonymous id and no verification-reference text (UX-D-47, PRD AC-11.14). After a failed export the admin runs access again (AC-11.11). A re-run of a failed erasure store needs the pairs and the verification reference entered again, because the PRD refused a re-run from a stored request (PRD §11.4; AC-11.12; confirmed, PRD Q-53); list entries are kept until the export expires (7 days) and the outcome stays in the 12-month audit log (AC-11.14); the retention of an entry of a request with no export is open, PRD Q-56 (RO-7). One access request yields one export (AC-11.1 "the export") and one per-store outcome table for the request (AC-11.2, UX-D-23); step-up fails; same user id in another tenant, untouched (AC-11.6); effect of restriction on access and erasure: pending design (CR-048, UX-Q-20 deferred to Phase 4).

### J-12 (US-12): Set retention per tenant

- Entry: Tenant retention (S-13); the tenant is chosen with the shared tenant selector (one selector in the admin navigation, no default, kept for the session, UX-D-48).
- Steps: 1. Choose tenant, current value in days shown. 2. Enter new value 1 to 396. 3. Save. 4. If shortening would destroy data (at least one stored event is older than the new retention; AC-12.5 wording "such that data would be destroyed"): step-up, then a confirmation that states the number of events and the date range that will be purged (the ingest-time dates of the oldest and newest affected events, because retention is measured from ingest time, AC-12.1); nothing is purged until confirmed (AC-12.5, UX-D-25). If no stored event is older than the new value, nothing would be destroyed, so there is no step-up and no confirmation (G-13). 5. Success message states the change applies at the next purge run.
- Exit: saved or cancelled.
- Error branches: invalid value, field-level message and existing value unchanged (AC-12.3); confirmation cancelled, nothing changes; step-up fails; retention of restricted data: pending design (CR-048, UX-Q-20).

### J-14 (US-14): Read the audit log

- Entry: Audit log (S-17).
- Steps: 1. Open viewer (the viewing is audited). 2. Filter by actor, action, tenant, date range. 3. Read matching records, 50 per page, newest first (UX-D-28).
- Exit: leave viewer.
- Error branches: no matches, empty state; invalid date range, message; user role requests it, S-18 (AC-14.3).

### J-16 (US-16): Manage accounts

- Entry: Accounts (S-15).
- Steps: 1. Create account (username, role); there is no initial password: a one-time setup link valid 24 hours is shown once to the admin (UX-D-12); creation needs step-up for both roles: admin creation (AC-8.5) and the setup-link issue for a "user" account (PRD Q-50 = yes, PRD rev 12). 2. The holder opens the link on S-19, sets a password and, for an admin, enrols TOTP (UX-D-12, UX-D-14). 3. Disable (confirmation), reset (step-up, one-time link shown once, 24 h, no email), change role (step-up, no confirmation; a role selector; promotion of a "user" to "admin" issues a one-time link for TOTP enrolment only, demotion removes admin access, UX-D-55), reset MFA of another admin (step-up, confirmation; a one-time link, 24 h, shown once, and S-19 has a TOTP-only variant, UX-D-56), unlock account (step-up). Actions offered by account status (UX-D-54): no enable action in v1; Disable for active or locked accounts; Reset credential and Change role for non-disabled accounts; Unlock for locked accounts only; Reset MFA for admin accounts only. 4. The holder of a reset link sets a password in S-19 (a password-only variant for an existing admin's credential reset, UX-D-56). The MFA-reset link, the S-19 variants, promotion and demotion are applied in PRD rev 13 (AC-16.12 to AC-16.14; pending HG-C-3; PI-22, PI-23).
- Exit: list updated.
- Error branches: missing role or duplicate username (AC-16.3); password under 12 characters or on the breached list (AC-16.4); last active admin disable, delete or demote refused (AC-16.6); step-up fails; link used twice or after 24 hours, or enrolment page older than 10 minutes (S-19; the link is consumed only on successful completion, UX-D-57).

### J-17 (US-17): Manage producer credentials

- Entry: Producer credentials (S-16).
- Steps: 1. Create credential for a tenant (one fixed permission, "Publish events to this tenant", UX-D-27) (step-up). 2. Secret shown once. 3. Rotate (step-up): both credentials accepted up to 24 hours, overlap expiry time shown; the list shows two linked rows, the old one "in overlap until <time> UTC" and the new one active (UX-D-59). 4. Revoke (confirmation) acts on the chosen row: refused within 60 seconds. A credential has no name in v1 and is identified by its id (UX-D-59).
- Exit: list updated, secret never shown again.
